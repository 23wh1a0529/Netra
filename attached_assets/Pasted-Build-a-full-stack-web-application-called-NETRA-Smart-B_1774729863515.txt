Build a full-stack web application called "నేత్ర (NETRA)" — Smart Bandobusth Duty Monitoring System for Anantapur Police. Tagline: "మూయని నేత్రం — The Eye That Never Closes."

Frontend: React, Vite, Tailwind CSS, Framer Motion, Leaflet.js, Recharts, react-hot-toast, lucide-react. Backend: Node.js, Express, Socket.io, SQLite via better-sqlite3. Use concurrently at the root so one command starts both servers. Vite proxies all API and socket requests to the backend. Load Google Fonts Rajdhani, Noto Sans Telugu, and JetBrains Mono in the HTML file.

BACKEND

Express server, CORS configured for frontend origin. Socket.io on the same HTTP server. Attach socket instance to request objects via middleware. Mount all route files. On socket connection: listen for panic button event and re-broadcast as panic triggered to all clients. Start simulation engine and escalation checker on startup.

Simulation engine runs every three seconds. Queries all active duties. For each officer except P007 (always offline): 70% chance drift within zone by a tiny random amount, 20% chance drift outside zone by a moderate random amount, 10% chance no update (emit officer offline event). For all updates: run haversine, update current location table, insert location log row, emit location update socket event.

Haversine uses Earth radius 6,371,000 meters. Standard formula: a = sin²(Δlat/2) + cos(lat1) × cos(lat2) × sin²(Δlng/2), distance = 2R × atan2(√a, √(1−a)).

Escalation checker runs every 30 seconds. In-memory breachStartMap keyed by officer ID. Queries officers currently outside zone. Records breach start time on first detection. If 5–10 minutes elapsed and no alert exists: create Level 1 EXIT alert, emit alert triggered. If 10–15 minutes and alert is still Level 1: upgrade to Level 2, emit alert escalated. If 15+ minutes and alert below Level 3: upgrade to Level 3, log simulated SMS to supervisor, emit alert escalated with supervisor ID. Remove officers back inside zone from the map.

Auto check-in/out timer runs every 10 seconds. If officer within 50m of zone and no check-in today: insert attendance row, emit auto check-in. If officer has open check-in and has been outside zone over 15 consecutive minutes: close attendance record, emit auto check-out.

API ROUTES

Auth: POST send-OTP — generate six-digit OTP, store in-memory by mobile, return OTP in response. POST verify-OTP — accept any six digits in demo mode, return demo token, role officer, officer ID P001. POST admin-login — accept username admin and password netra@2025, return token and role admin, else 401.

Personnel: GET list — join personnel, duties, current location, most recent attendance row — return id, name, rank, mobile, supervisor_id, zone name, duty_id, zone lat/lng/radius, current lat/lng, inside_zone, distance, last_updated, compliance_score, violation_count, check_in, and computed status (in_zone if inside_zone true, breach if inside_zone false, late if no check-in today, offline if no current_location row or last_updated over five minutes ago). POST create — auto-generate next ID, insert personnel and duty row, return new officer. PUT update — update fields. DELETE — set duty status inactive.

Dashboard stats: GET — return totalOfficers, inZone, breaches, late, offline, averageCompliance, todayCheckins, and hourlyBreaches array of 24 objects each with hour and count.

Alerts: GET with optional type/level/status query params — last 50 joined with officer name ordered by timestamp desc. POST create — insert alert, return it. PUT acknowledge — set status acknowledged, emit alert acknowledged event. PUT escalate — increment level capped at 3, log SMS to supervisor at level 3, emit alert escalated.

Location: POST update — receive officer ID, lat, lng, fetch duty zone, run haversine, update current location, insert location log, emit location update, return insideZone, distance, status. GET by officer ID — return current location and distance from zone center.

Attendance: GET list joined with officer names. POST check-in — insert row with current timestamp. POST check-out — close most recent open row, compute total minutes.

Face verify: POST — receive officer ID and image base64, fetch current location and duty zone, compute distance, return failure if over 50m, else simulate 80% pass 20% fail, insert face verification row with realistic confidence score, trigger check-in on pass, return result, confidence, officer name. GET logs — last 20 joined with officer names ordered by timestamp desc.

SMS: POST send — insert SMS log row, return success. GET logs — all rows ordered by sent-at desc. DELETE by ID.

Duties: GET list joined with personnel. POST, PUT, DELETE (soft delete sets status inactive).

Demo: POST trigger-breach — set P003 current location to lat 14.6798 lng 77.5975 inside_zone false distance 80, insert Level 1 EXIT alert, emit location update and alert triggered. POST escalate-L3 — find P003's latest alert, set level 3, log simulated SMS, emit alert escalated. POST reset — set all current_location rows to inside_zone true distance 10, restore P003 to inside RTC Bus Stand zone, delete demo alerts, emit stats update with clean data.
